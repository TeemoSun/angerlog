# 🌋 情绪瓶 — 生气记录应用 详细设计文档

> 版本：v1.1  
> 文档状态：修订（基于设计评审决策更新）  
> 目标用户：希望觉察并管理自身情绪的个人用户（单用户部署）

## 1. 项目概述

### 1.1 产品愿景
**情绪瓶**是一个轻量级情绪记录工具，将每次生气抽象为“向瓶中投入一颗小球”，通过可视化的积累和统计分析，帮助用户觉察情绪触发规律，提升情绪管理能力。

### 1.2 核心功能
- **安全登录**：唯一账号，密码由环境变量配置，应用启动时自动 upsert 到数据库；采用双 Token（短 access + 长 refresh）+ HttpOnly Cookie，支持 30 天免登自动续期。
- **记录生气**：填写原因、程度（1-10）、分类（可选），提交后以小球动画落入瓶中；高强度（≥8）记录提交前弹出 4-7-8 呼吸引导。
- **解决标记**：对已有记录标记“已解决”，并填写解决办法，记录解决时间。
- **查看记录**：完整列表展示所有记录，支持筛选（按程度、分类、是否解决）；删除采用软删除，保留历史。
- **统计分析**：
  - 总生气次数
  - 程度分布（平均、最高、最低）
  - 解决率
  - 趋势折线图（按日/周/月）
  - 热点图（星期 × 小时，显示高频时段，按用户时区计算）
- **瓶子水位**：瓶子水位随累计记录数上升，直观呈现“情绪积压感”。
- **数据导出**（可选）：导出为 CSV / JSON。

### 1.3 部署边界说明
- 本项目**只提供 HTTP 服务**，HTTPS / TLS 由上层反向代理（不在本项目范围内）负责。
- 因此本项目部署编排中**不含 Nginx 与证书管理**；CORS、安全传输相关说明均按此前提给出。

## 2. 用户角色与权限
- **单用户模式**：系统仅预设一个账号，无注册功能。
- 账号密码通过后端环境变量 `USERNAME` 和 `PASSWORD_HASH` 配置（密码使用 bcrypt 存储，cost factor = 12）。
- **账号初始化**：应用启动时根据环境变量对 `users` 表执行 upsert（存在则更新 `password_hash`，不存在则插入），保证多实例幂等。
- **认证机制**：双 Token
  - access token：短有效期（15 分钟），置于 HttpOnly Cookie。
  - refresh token：长有效期（30 天），置于 HttpOnly Cookie（`HttpOnly + Secure + SameSite`）。
  - 所有 API 需验证 access token（Cookie 自动携带），配合 CSRF 防护。

## 4. 数据库设计 (PostgreSQL)

> **时区策略**：`created_at` / `resolved_at` 等 `TIMESTAMPTZ` 字段一律以 UTC 存储；所有“星期/小时”维度的统计在查询时按**用户时区**换算（`users.timezone`）。因此不再使用基于 UTC 的生成列，改为在统计 SQL 中用 `EXTRACT(ISODOW FROM created_at AT TIME ZONE <tz>)` 等动态计算。

### 4.1 用户表 `users`
仅存一条记录（预设账号）。
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,        -- bcrypt(cost=12) 加密
    timezone VARCHAR(50) NOT NULL DEFAULT 'Asia/Shanghai',  -- 统计时区
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 4.2 Refresh Token 表 `refresh_tokens`
用于 refresh token 轮换与吊销。
```sql
CREATE TABLE refresh_tokens (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash VARCHAR(255) NOT NULL,           -- refresh token 的哈希（不存明文）
    expires_at TIMESTAMPTZ NOT NULL,
    revoked BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_refresh_user ON refresh_tokens(user_id);
CREATE INDEX idx_refresh_expires ON refresh_tokens(expires_at);
```

### 4.3 生气记录表 `anger_logs`
```sql
CREATE TABLE anger_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

    trigger_reason TEXT NOT NULL,
    intensity SMALLINT NOT NULL CHECK (intensity BETWEEN 1 AND 10),
    category VARCHAR(20)
        CHECK (category IN ('工作','家庭','交通','社交','其他') OR category IS NULL),

    is_resolved BOOLEAN DEFAULT FALSE,
    resolution_method TEXT,

    is_deleted BOOLEAN DEFAULT FALSE,           -- 软删除标记
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    resolved_at TIMESTAMPTZ                      -- 当 is_resolved 变为 true 时自动填写
);

-- 索引
CREATE INDEX idx_logs_user_created ON anger_logs(user_id, created_at DESC) WHERE is_deleted = FALSE;
CREATE INDEX idx_logs_intensity ON anger_logs(intensity) WHERE is_deleted = FALSE;
CREATE INDEX idx_logs_resolved ON anger_logs(is_resolved) WHERE is_deleted = FALSE;
CREATE INDEX idx_logs_category ON anger_logs(category) WHERE is_deleted = FALSE;
```

> **说明**：
> - 所有列表 / 统计查询默认带 `is_deleted = FALSE` 过滤（统计排除已删除数据）。
> - `day_of_week` / `hour_of_day` 不再作为生成列，改为查询时按 `users.timezone` 动态计算（见 5.5）。
> - 星期使用 ISO 语义：`ISODOW`（周一=1 … 周日=7），与前端“周一至周日”一致。

### 5.3 API 端点设计

#### 系统
| 方法 | 路径 | 描述 |
|------|------|------|
| GET  | `/health` | 健康检查（含 DB 连通性），供 Docker healthcheck / 上层探活 |
| GET  | `/api/v1/auth/public-key` | 返回 RSA 公钥（供前端加密密码） |

#### 认证
| 方法 | 路径 | 描述 |
|------|------|------|
| POST | `/api/v1/auth/login` | 登录；请求体含 RSA 加密的密码；成功后通过 Set-Cookie 下发 access/refresh |
| POST | `/api/v1/auth/refresh` | 用 refresh cookie 换新 access（轮换 refresh） |
| POST | `/api/v1/auth/logout` | 吊销 refresh token 并清除 cookie |

#### 记录管理
| 方法 | 路径 | 描述 |
|------|------|------|
| POST   | `/api/v1/logs` | 创建记录 |

| PUT    | `/api/v1/logs/{id}` | 更新（用于标记解决） |

### 5.5 关键业务逻辑示例

**标记解决时自动填写 `resolved_at` 并更新 `updated_at`**（Service 层）：
```python
async def update_log(log_id: UUID, update_data: LogUpdate, user_id: UUID):
    log = await repo.get_by_id(log_id, user_id)  # 内部过滤 is_deleted=False
    if update_data.is_resolved is True and not log.is_resolved:
        update_data.resolved_at = datetime.now(timezone.utc)
    elif update_data.is_resolved is False:
        update_data.resolved_at = None
    update_data.updated_at = datetime.now(timezone.utc)
    return await repo.update(log_id, update_data)
```

**热力图按时区计算**（Repository 层，`tz` 来自 `users.timezone`）：
```python
SELECT EXTRACT(ISODOW FROM created_at AT TIME ZONE :tz)::int AS day_of_week,
       EXTRACT(HOUR  FROM created_at AT TIME ZONE :tz)::int AS hour_of_day,
       COUNT(*) AS count
FROM anger_logs
WHERE user_id = :uid AND is_deleted = FALSE
GROUP BY day_of_week, hour_of_day;
```

- **移动端适配**：采用 Tailwind 响应式断点，主界面在窄屏下转为单列、底部 Tab 导航，确保手机端随手记录体验。

### 6.3 核心交互流程

#### (1) 扔小球（记录生气）
- 点击「➕ 扔小球」或点击瓶口 → 弹出模态框。
- 表单：
  - 原因：文本域 (必填，长度上限 500 字符)
  - 程度：滑块 (1-10)，带当前值显示
  - 分类：下拉选择 (工作/家庭/交通/社交/其他)
- **高强度干预**：当程度 ≥ 8 时，提交按钮上方出现 4-7-8 呼吸引导动画（吸气 4s → 屏息 7s → 呼气 8s），用户可选择跟随后再提交，也可直接提交。
- 提交按钮 → 调用 `POST /logs` → 成功时触发**小球掉落动画**：
  - 小球从瓶口出现，带有重力弹跳效果 (Framer Motion `spring` 物理)。
  - 根据程度决定球体大小和颜色（1-3 淡黄，4-6 橙黄，7-8 橙红，9-10 深红）。
  - 落入瓶中后，瓶内小球数量 +1，位置随机分布（可使用简单的碰撞检测避免重叠）。
- **水位联动**：记录成功后瓶内水位按累计数量比例上升（带过渡动画）。

#### (2) 标记解决
- 在「完整记录」列表中，每条记录有「解决」按钮（如果未解决）。
- 点击后弹出小窗口输入「解决办法」→ 提交 `PUT /logs/{id}` 更新。
- 记录卡片上标记 ✓ 和解决时间。

#### (3) 查看统计
- 点击「📈 统计图表」切换至统计面板（或侧边抽屉）。
- 展示：
  - 汇总卡片：总次数、平均强度、最高强度、解决率。
  - 趋势折线图（可切换日/周/月）。
  - 分类饼图。
  - 热力图：横轴为星期（周一至周日），纵轴为小时（0-23），颜色深浅表示频率（数据按用户时区计算）。

#### (4) 自动刷新 Token
- Axios 拦截器：access token 失效（40102）时自动调用 `/auth/refresh`（携带 refresh cookie）获取新 access 并重试原请求；refresh 也失效则跳转登录页。
- Axios 实例配置 `withCredentials: true`，所有请求自动携带 HttpOnly cookie。

### 6.4 技术实现要点

- **状态管理**：使用 Zustand 存储筛选条件、`logs` 列表；登录态由 cookie 维护，前端不持有 token 明文。
- **CSRF 防护**：前端从首个 GET 响应（或专用接口）读取 CSRF token 并存内存，在写请求头中携带 `X-CSRF-Token`；后端校验。
- **路由**：使用 React Router v6，保护 `/` 路径（未登录跳转 `/login`）。
- **UI 组件**：shadcn/ui 的 Dialog、Slider、Select、Card、Button 等。
- **图表**：Recharts 的 `LineChart`、`PieChart`、`Heatmap`（可用 `Scatter` 或自定义矩形块）。
- **背景粒子**：tsParticles，配置为缓慢漂浮的浅色光点。
- **呼吸引导**：基于 Framer Motion 的圆形缩放动画，配合文字提示与计时。

## 7. 安全方案

### 7.1 登录密码传输加密
- 项目仅提供 HTTP 服务，HTTPS 由上层代理负责；作为纵深防御，登录密码在前端使用 RSA 公钥加密（2048 位）后再传输，后端用私钥解密后与数据库 bcrypt 哈希比对。
- RSA 密钥对存放在后端 `certs/` 目录，公钥通过 `GET /api/v1/auth/public-key` 提供给前端。

### 7.2 双 Token 会话管理
- access token：有效期 15 分钟，`HS256` 签名，`SECRET_KEY` 来自环境变量；置于 HttpOnly Cookie。
- refresh token：有效期 30 天，置于 HttpOnly Cookie（`HttpOnly + Secure + SameSite=Lax/Strict`）；服务端仅存其哈希于 `refresh_tokens` 表，支持轮换与吊销。
- `/auth/refresh` 校验 refresh token 有效且未吊销，签发新 access 并轮换 refresh。
- `/auth/logout` 吊销当前 refresh 并清除 cookie。

### 7.3 CSRF 防护
- 因认证凭据存于 cookie，写操作（POST/PUT/DELETE）须携带 `X-CSRF-Token` 请求头，后端 `dependencies.py` 校验；配合 cookie 的 `SameSite` 属性。

### 7.4 登录速率限制 / 失败锁定
- 登录接口按 IP 限流（默认 5 次 / 5 分钟，可由 `LOGIN_RATE_LIMIT` 配置）；超限返回 `42901`。
- 连续失败触发临时锁定，避免暴力破解。

### 7.5 其他安全措施
- 所有 API 响应隐藏详细错误信息（生产环境仅返回错误码与通用 message）。
- 启用 CORS，仅允许 `CORS_ORIGINS` 配置的前端来源，且开启 `allow_credentials`。
- bcrypt cost factor = 12；`SECRET_KEY` / `CSRF_SECRET` 从环境变量读取，缺失即启动失败。

## 8. 部署与运维

### 8.1 Docker Compose 方案
> 不含 Nginx；HTTPS 由上层反向代理提供。前端构建产物可由后端 StaticFiles 托管，或交由上层代理直接托管 `frontend/dist`。

```yaml

services:
  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: emotion_bottle
      POSTGRES_USER: app_user
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app_user -d emotion_bottle"]
      interval: 10s
      timeout: 5s
      retries: 5
    ports:
      - "5432:5432"

  backend:
```

### 8.2 环境初始化
- **环境变量校验**：后端启动时由 Pydantic Settings 校验所有必需变量，缺失即失败退出并列出缺失项。
- **用户 upsert**：启动事件中执行 `users` upsert（按 `USERNAME`），同步 `password_hash` 与 `timezone`。
- 首次启动时通过 Alembic 自动执行数据库迁移（可在启动脚本中运行 `alembic upgrade head`）。
- 预生成 bcrypt 密码哈希工具：`python -c "import bcrypt; print(bcrypt.hashpw(b'your_password', bcrypt.gensalt(12)).decode())"`。

### 8.3 日志与监控
- 后端日志输出到 stdout，由 Docker 收集。
- `/health` 端点供 Docker healthcheck 与上层负载均衡探活。
- 可集成 Sentry 进行错误追踪（可选）。
